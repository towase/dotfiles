html-report テンプレート

Claude の HTML Artifact と同じ設計規約でローカル HTML を書くための骨格です。各節がそのまま部品の実例になっています。コピーして :root のトークンと本文を差し替えてください。

対象
/tmp/<topic>.html に書き出す「確認」と「レポート」
根拠
Artifact の publish 時 skeleton と artifact-design skill の fundamentals。手元の Artifact 3 件の共通部分

要点

.facts は数字を先に見せる所、.cards は並列の要点に使う。カードの左縁色は意味色（good / warn / bad）で、飾りではなく状態を表す。

3フォントの役割（display / body / mono）
6 + 5色トークン（基本 6 色 + 意味色 5 色）
960px本文カラムの最大幅

そのまま使える

Google Fonts が読めない環境でも Hiragino Sans に落ちて崩れない。JS は使っていない。

主題に合わせて変える

アクセント色と display 書体は主題ごとに決める。手引きなら明朝（Shippori Mincho B1）も候補。

やらない

ダークモード分岐、外部 JS、mermaid、絵文字見出し、全カードへの同じ影。

調査結果

.rows は番号に順序の意味があるときに使う。順序がなければ .cards か箇条書きにする。

  1. 1
    Artifact は本文だけを書き、骨格はサービスが付ける 事実

    publish 時に doctype・meta・リセット CSS（14px システムフォント、白地）が先頭に差し込まれる。ローカルでは <head> とリセットを自分で書く。

  2. 2
    色とフォントは :root のトークンに集約されている 事実

    地・紙・文字・補助・罫線・アクセントの 6 色と、good / major / warn / bad / off の意味色。部品の CSS は var() だけを使う。

  3. 3
    図はインライン SVG で、文字は currentColor 確認済み

    3 件とも svg text { fill: currentColor } を置き、塗りと線を CSS 変数で指定していた。

選択肢

「確認」では .options に案を並べ、推奨案に .recommended と .chip.accent を付ける。各案はコードブロック + Pros / Cons。

案 A: テンプレートを複製して書く

推奨
cp ~/.agents/skills/html-report/template.html /tmp/<topic>.html
  • Artifact と同じ骨格・部品が最初からそろう
  • トークンを変えるだけで主題に合わせられる
  • 使わない部品の CSS が残る（害はない）

案 B: 毎回ゼロから設計する

非推奨
（骨格・トークン・部品を都度書く）
  • 主題ごとに自由度が高い
  • レポートごとに見た目がばらつく
  • 骨格やフォールバックの書き漏れが起きやすい

推奨: 案 A

結論・推奨案・次のアクションは .callout に 1 つだけ置く。読者が最後に見る所なので、ここだけアクセント色の面を使う。
